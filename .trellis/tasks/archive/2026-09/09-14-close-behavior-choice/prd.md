# 主窗口关闭行为可配置

父任务：`.trellis/tasks/09-14-issue-633-close-behavior-webdav`
来源：issue #633 诉求 1

## Goal

把主窗口关闭按钮的行为从硬编码改为用户可配置的三值偏好，并在用户从未做过选择时通过一次性询问框把这个选择交给用户，消除「以为退出了其实只是隐藏」的认知偏差。

## 背景与取舍

现状 `src-tauri/src/lib.rs:1149`：`CloseRequested` 里 `can_hide_to_tray()` 为真就 `window.hide()`，为假就 `app.exit(0)`。用户无从知晓，也无从改变。

参考实现 LiveAgent 用的是**纯设置项**（`commands/app/app.rs`）：二值 `minimize | exit`，前端启动时与改动时推给后端，后端 `AtomicU8` 缓存，`CloseRequested` 读它分支。issue #633 第一张截图给的就是这个设置项的样子——「关闭窗口」分组下两行：「最小化到托盘 / 关闭窗口后应用继续在后台运行，可从托盘恢复」与「退出应用 / 关闭窗口即退出；**有运行中的终端时会先确认**」。

codeg 采用**三值 `ask | minimize | exit`，默认 `ask`**。多出的 `ask` 是为了解决 issue 作者真正的痛点——发现不了。纯设置项对从不翻设置页的用户等于不存在；而 `ask` 只在首次关闭时出现一次，用户勾选「记住我的选择」后偏好即被固化，之后与纯设置项完全等价，同时设置页里三个选项都能随时改回。

## Requirements

### R1 偏好模型

- 偏好值为 `ask` | `minimize` | `exit`，默认 `ask`。
- 持久化到 `app_metadata` 表（键 `system_close_behavior_settings`，JSON），与 `system_settings.rs` 中既有系统偏好一致。
- 关闭事件处理是同步上下文，不能 await 数据库；进程内维护一个原子缓存，启动时从数据库加载，更新命令写库成功后同步刷新缓存。
- 未知/损坏的存储值按默认值 `ask` 处理，不报错。

### R2 关闭分支行为

- `minimize`：`prevent_close()` + 隐藏主窗口到托盘（等价于当前行为）。
- `exit`：走真实退出路径，与托盘菜单「退出 Codeg」一致，保证 ACP 连接断开、终端进程回收等既有清理逻辑照常执行。
- `ask`：`prevent_close()` + 向前端发事件弹出询问框，用户做出选择后由前端调用命令决定本次动作。
- 托盘不可用时（`can_hide_to_tray() == false`，即 Linux 或托盘安装失败）：忽略偏好，一律真实退出。这是既有约束——隐藏主窗口会让桌宠等 `skip_taskbar` 辅助窗口变成无法召回的孤儿进程。

### R2.1 退出前的终端确认

采纳 issue 截图里的「有运行中的终端时会先确认」。这不是锦上添花：现状 `lib.rs` 的退出路径直接 `tm.kill_by_owner_window(&label)` 杀掉主窗口下所有终端，只留一行 `killed_terminals=N` 日志，用户毫无提示地丢掉正在跑的构建或长任务。

- 凡是**由关闭按钮触发的真实退出**（偏好为 `exit`、询问框里选了退出、以及托盘不可用时的强制退出），在执行退出前先查主窗口下存活终端数；大于 0 则 `prevent_close()` 并弹确认框，说明「有 N 个终端正在运行，退出将结束它们」，用户确认后才退出。
- 存活终端数由 `TerminalManager` 提供同步查询（`list_with_exit_check` 已有存活判定逻辑，在其上加一个按 owner window 计数的方法，不另写一套判活）。
- 询问框（R3）与本确认**不叠成两个对话框**：`ask` 状态下若已有终端在跑，直接在询问框内联一行警告文字，用户选「退出」即视为已确认。
- 托盘菜单「退出 Codeg」维持现状，不加确认——那是明确的退出意图，且属既有行为，不在本任务范围。

### R3 询问对话框

- 由主窗口前端渲染，与应用现有对话框风格一致（shadcn `AlertDialog`/`Dialog`）。
- 两个动作：「最小化到托盘」「退出 Codeg」；一个复选框：「记住我的选择」。
- 勾选后写入对应偏好（`minimize`/`exit`）并执行该动作；不勾选只执行本次动作，偏好保持 `ask`。
- 对话框打开期间重复点击关闭按钮不得叠加弹出多个对话框。
- 用户通过 ESC / 点遮罩关闭对话框视为「取消关闭」，窗口保持原状，不写偏好。

### R4 设置页入口

- 落在「常规」设置页（`src/components/settings/general-settings.tsx`）中，与既有 `SettingCard` / `SettingRow` 结构一致。
- 三选一控件（Select 或 RadioGroup），选项文案需说明各自后果。
- 托盘不可用平台上该项禁用，并显示原因说明（该平台关闭即退出）。
- 仅桌面模式渲染；Web/服务器模式不显示。

### R5 国际化

- 所有新增文案进入 `src/i18n/messages/*.json` 全部 10 种语言，不留缺键。

## Acceptance Criteria

- [ ] 全新安装首次点主窗口关闭按钮，弹出询问对话框，窗口未关闭也未隐藏
- [ ] 在对话框中选「退出 Codeg」且不勾记住 → 应用退出；重新启动后再次点关闭仍然弹询问框
- [ ] 在对话框中选「最小化到托盘」且勾选记住 → 窗口隐藏、托盘可召回；此后点关闭直接隐藏不再弹框；设置页显示「最小化到托盘」
- [ ] 设置页把偏好改为「直接退出」后，在无终端运行时点关闭按钮真实退出，且 ACP 连接与终端进程被正常回收（日志中出现既有的 `disconnected_connections` / `killed_terminals` 记录）
- [ ] 偏好为「直接退出」且有 1 个以上终端在运行时点关闭按钮，先弹确认框并写明终端数量；取消则窗口保持原状且终端未被杀；确认则正常退出
- [ ] 偏好为「每次询问」且有终端在运行时，询问框内联显示终端警告，且不会出现第二个确认框
- [ ] 托盘不可用平台上有终端运行时点关闭，同样先确认再退出
- [ ] 设置页把偏好改回「每次询问」后，下次点关闭重新弹出询问框
- [ ] 对话框打开时连点关闭按钮，不会出现第二个对话框
- [ ] 对话框按 ESC 取消后，窗口既没隐藏也没退出
- [ ] 托盘菜单「退出 Codeg」在任何偏好下都直接退出，不弹询问框
- [ ] Linux（或强制 `can_hide_to_tray()` 为假）下点关闭直接退出，设置项为禁用态并有解释文案
- [ ] 数据库中该键存入非法值时，应用按「每次询问」运行且不报错
- [ ] `pnpm eslint .` / `pnpm test` / `pnpm build` 全绿
- [ ] `cargo test --features test-utils` / `cargo clippy --all-targets --features test-utils -- -D warnings` 全绿
- [ ] `cargo check --no-default-features --bin codeg-server` 全绿（桌面专属代码正确 cfg 隔离）
- [ ] 10 种语言消息文件均含新增键

## 非目标

- 不改动托盘菜单结构
- 不引入「最小化到任务栏」第三种动作（与托盘隐藏语义重叠，且托盘不可用时同样不安全）
- 不改动桌宠、设置窗等辅助窗口的关闭语义
